# AI-Assisted Label Naming - Research & Prototype Plan

## Overview

This document captures research into using LLMs and AI models for suggesting
meaningful label names for unlabeled code/data in disassembled ROMs.

## Approach Categories

### 1. Local LLM (Ollama / llama.cpp)
- **Pros:** Privacy, no API costs, offline capable, fast for small prompts
- **Cons:** Lower quality than cloud models, requires GPU for speed
- **Models to evaluate:** CodeLlama 7B/13B, DeepSeek Coder, Qwen2.5-Coder
- **Integration:** HTTP API via Ollama, feed disassembly context, get name suggestions

### 2. VS Code Copilot Integration
- **Pros:** Already installed, high quality, user-familiar
- **Cons:** Requires subscription, not programmable from library code
- **Integration:** Copilot Chat participants or inline suggestions in .pasm files
- **Approach:** Custom Copilot extension that reads Pansy metadata + disassembly

### 3. Cloud API (OpenAI / Anthropic / etc.)
- **Pros:** Highest quality suggestions, large context window
- **Cons:** Cost, privacy concerns, requires internet
- **Integration:** Direct API calls with batched prompts

## Prompt Engineering Strategy

### Context Window Design
For each unlabeled address, provide:
1. **Surrounding code** (8-16 instructions before/after)
2. **Cross-reference context** (who calls this, what it calls)
3. **Known symbols** nearby (hardware registers, existing labels)
4. **Platform context** (NES/SNES/GB etc. and common patterns)
5. **CDL classification** (code vs data, sub-entry vs jump target)

### Example Prompt Template
```
Platform: NES (6502)
Context: Function at $C100, called from 3 locations, calls $C200 and writes to $2006/$2007 (PPUADDR/PPUDATA).

Code:
  $C100: LDA #$20
  $C102: STA $2006
  $C105: LDA #$00
  $C107: STA $2006
  $C10A: LDX #$00
  $C10C: LDA $0400,X
  $C10F: STA $2007
  $C112: INX
  $C113: CPX #$20
  $C115: BNE $C10C
  $C117: RTS

Known symbols: $2006=PPUADDR, $2007=PPUDATA, $0400=nametable_buffer

Suggest a descriptive function name for the routine at $C100.
```

**Expected response:** `upload_nametable_row` or `write_ppu_nametable`

### Confidence Scoring
- **High (0.8-1.0):** Strong hardware register usage patterns, clear loop structures
- **Medium (0.5-0.8):** Some context clues but ambiguous purpose
- **Low (0.0-0.5):** Minimal context, generic operations

## Implementation Plan

### Phase 1: Batch Suggestion API
```csharp
public interface ILabelSuggester {
    Task<List<LabelSuggestion>> SuggestLabelsAsync(
        SuggestionContext context,
        CancellationToken ct = default);
}

public record LabelSuggestion(
    uint Address,
    string SuggestedName,
    double Confidence,
    string Reasoning);

public record SuggestionContext(
    byte Platform,
    byte[] RomData,
    PansyLoader Metadata,
    IReadOnlyList<uint> TargetAddresses);
```

### Phase 2: Ollama Integration
- `OllamaLabelSuggester : ILabelSuggester`
- HTTP client to local Ollama instance
- Configurable model selection
- Prompt template system

### Phase 3: Review Workflow
- Suggestions written to JSON file for human review
- Accept/reject/edit per suggestion
- Accepted suggestions → LabelMergeEngine as InternetDatabase or AutoGenerated source
- Track suggestion accuracy over time

## Data Sources for Training/Few-Shot

### Known Good Label Sets
- **nesdev.org** community disassemblies (SMB, Zelda, Mega Man)
- **snesdev** community projects
- **GBDK** example code with labeled subroutines
- Existing Pansy files with user labels

### Pattern Libraries
Common subroutine patterns with canonical names:
- PPU write loops → `upload_tiles`, `write_nametable`, etc.
- Controller reading → `read_joypad`, `poll_input`
- Sound engine → `play_sfx`, `update_music_frame`
- DMA transfers → `oam_dma`, `vram_transfer`
- RNG routines → `random`, `prng_next`
- Decompression → `decompress_lz`, `decode_rle`
